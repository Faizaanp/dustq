# T6 report — the probe session, and the four bugs found before it ever ran

Task: T6 probe suite (Plan v3.1 section 5). Date: 2026-11-02 (CPU) / the Colab session it
prepares for. Nothing in this report is a measured L4 result; every number here is from a CPU
fixture (tiny model, 2-backprop-step checkpoint) or from a one-off script, tagged [code].

## What happened

The 2026-11-02 Colab session printed the G1 loss rows (recorded in T4.md), then exited 1 at
the **first** probe command with no inner output:

```
=== S probes L4d256_1M_w1p58a4_backprop_K0_s0 (probes 3,2,5,0, forward=fake) ===
CalledProcessError: ... returned non-zero exit status 1.
```

## Root causes (all verified against the committed code)

### 1. `results/` was never linked from Drive — the actual crash [code]

`results/` is gitignored (`.gitignore:5`), so `git archive -o dustq.zip HEAD` ships a repo with
no results tree. `scripts/colab_probe.py` symlinked only `data`:

```python
if not Path("data").exists():
    os.symlink(DRIVE_DATA, "data")
```

`ProbeContext.__post_init__` then opens `Path(cfg.output_dir) / cfg.run_id / "best.pt"`
(`output_dir: results` in every PCKPT yaml) → `FileNotFoundError` → exit 1, **before the first
gradient of the session**, with nothing printed because `subprocess.run` swallowed it.

Fixed: link `results` too, plus a preflight block that asserts the data files, the alpha table
and all five checkpoints (four S + one M) exist *before* the GPU time starts, and a
`run_checked()` wrapper that prints stdout/stderr tails on failure instead of vanishing.

### 2. `dust_grads` registered the act-quant hooks in the wrong order [code]

`dust_grads` called `_ensure_hooks("identity")` **before** constructing `DUSTQ`. PyTorch
forward pre-hooks chain (each hook sees the previous hook's returned value — verified
empirically), and upstream registers its `o@l` noise hook inside `DUST.__init__`. Every other
Dust path in the repo builds the estimator first (`train.py:97→104`, `runner.py:61→66`,
`benchmark.py:37→43`); the probes were the sole outlier.

Consequence, measured with a hook-order A/B on the exact path (tf32) [code]:

| site | correct order | reversed order | ratio |
| --- | --- | --- | --- |
| attn.c_q | 0.001697 | **0.000000** | 0.000 |
| attn.c_k | 0.002282 | **0.000000** | 0.000 |
| attn.c_v | 0.002122 | **0.000000** | 0.000 |
| attn.c_proj | 0.001895 | 0.001895 | 1.000 |
| mlp.c_fc | 0.003586 | 0.003586 | 1.000 |
| mlp.c_proj | 0.003158 | 0.003158 | 1.000 |

On the exact paths the attention-internal gradients are **exactly zero**: Dust's `o@l` jitter is
added to an already-quantized input, and `QLinear`'s exact path computes from codes taken from
the clean input — so the perturbation never reaches the matmul, the hub-site rewards vanish,
and `local_errors` has no targets. On the fake path (the session's `--dust-forward fake`) the
jitter still propagates, but *after* quantization: Q/K/V cosines between the two orders are
+0.90, i.e. a different function, not a degenerate one [code].

Either way the Dust probes were measuring a different function from the one Tier B trains.
Fixed: construct `DUSTQ` first, then force-reregister the act hooks (`force=True`, needed
because `DUSTQ.close()` removes Dust's hooks but leaves ours in place — a cached registration
would silently rotate back to the wrong order on the next call). Locked in by
`test_dust_grads_hook_order`, which asserts the ordering across **two consecutive** calls.

### 3. `probe_sigma_delta` built its sigma dict and never passed it [code]

The old code built `sigmas[site] = frac * max(delta, 1e-5)` and then called
`ctx.dust_grads(seed=0, population=k)` with no `sigmas=` argument — so the whole σ–Δ sweep ran
at the default noise and varied `frac` in name only. Worse, the dict was keyed by the probes'
own site names (`attn.c_q`, `mlp.c_fc`, …); wiring it through as written would have hit
`DUSTQ.__init__`'s `ValueError: unknown sigma keys`, because `DEFAULT_SIGMAS` is keyed by
`writer / hidden / emb / hub_shallow / hub_deep / head / local / scalar` (`dust_ext.py:40-44`).

Fixed: `qmodel.site_sigma_key()` is now the single source of truth for the site→sigma-key map
(the inverse of the old `site_sigma`, with the hub split by depth), `site_sigma` delegates to it
(behaviour unchanged — asserted value-for-value in `test_site_sigma_key_mapping`), and the
sweep passes `sigmas=` per (frac, K).

### 4. `median_step` hardcoded `/255`, and the flip rate was never computed [code]

`return acts.abs().median().item() / 255.0` is an 8-bit absmax assumption; probe 5 runs on A4/A2
under `mse_alpha`, where the code spacing *is* the per-token scale. Replaced with
`median_delta()` = median of `_act_scale`. The promised flip rate was never computed (the spy
hooks were removed before the sweep) — now computed per frac from a bounded input slice.

**The diagnostic works** [code, tiny smoke model, A4; mean over the six act sites]:

| σ (×Δ) | 1/8 | 1/4 | 1/2 | 1 | 2 | 4 | 8 | 16 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| flip rate | 0.000 | 0.044 | 0.283 | 0.560 | 0.740 | 0.839 | 0.887 | 0.912 |

Monotone in σ, and 0.560 at exactly 1×Δ (Q / K / V / MLP-in all 0.607, Attn out 0.533, and
0.398 for the unsigned MLP-out site) — the analytically expected magnitude for noise one
code-step wide over a near-uniform phase distribution. Sub-¼Δ noise moves essentially no codes
on A4, which is the dead-zone reading this probe exists to produce.

## Effect on earlier claims

- **G1 stands.** Its gradient criterion is a bf16-vs-fp32 comparison on one unchanged function,
  and its per-group minimum (+0.938, c_k) was non-zero, so that probe run predates the exact-path
  plumbing and measured the (order-buggy) fake path. The dtype conclusion is unaffected; the
  absolute Dust-vs-backprop cosines from before this fix are *not* comparable to post-fix ones.
- The 6/6 probe suite that passed earlier exercised `task=smoke` only (absmax +
  `allow_lowbit_absmax=True`). The real session uses `task=PCKPT` (mse_alpha + the frozen alpha
  table + `allow_lowbit_absmax=False`) — that combination had never run on CPU and is now
  covered by `test_pckpt_task_probe_path`.
