# T1/T2 report — Infrastructure and data (Phase 1, local part)

Date: 2026-10-11. The only remaining T1 item is the **Colab L4 benchmark session** (section 4 below); everything CPU-testable locally is done and green.

## T1: what was built

- `dustq/config.py` — `RunConfig` with upstream-tuned defaults per (tokens, population, method): Dust cells from `dust.DEFAULT_CONFIGS`, backprop from `baselines/backprop.py`; run_id naming `{size}_{tokens}_{prec}_{method}_K{K}_s{seed}`; the v1 §6 runs.csv schema.
- `dustq/train.py` — the resumable `Runner`: one entry point for dust/backprop; upstream-parity protocol (shuffled prefix by `seed+1`, eval every `eval_interval`, `best.pt`, `result.json` with test-at-best-val, `metrics.jsonl`); exact resume from `ckpt.pt` = model + optimizer + **DUSTQ noise-generator state** + step + history; atomic ckpt writes; fp32-safe `evaluate` (upstream's hard-codes bf16 — REPO_MAP note).
- `dustq/queue.py` + `scripts/run_queue.py` — idempotent queue: skips complete runs, resumes partial ones, logs failures to runs.csv, never deletes.
- `scripts/benchmark.py` — s/step (3 measured + 1 warmup) and peak memory for S/M × K ∈ {256, 1k, 4k} × {fp, w1.58a4}, an nrep=16 (K=16384) memory probe, and a 2-concurrent-S throughput test; `--scale tiny` for local pipeline checks, `--scale real` for the L4.
- `scripts/make_configs.py` — emits the Tier R configs (18 YAMLs, committed under `configs/`).
- `scripts/colab_t1.py` — the paste-into-one-cell Colab session (env check, benchmark, GPU resume test, CU instructions).

## Deviations

1. `scripts/queue.py` → `scripts/run_queue.py`: the filename shadowed the stdlib `queue` module (torch imports it), breaking any script run from `scripts/`. Discovered when `make_configs.py` crashed; recorded here per the rules.
2. The plan's file map put the resumable entry point in `runner.py`; it lives in `dustq/train.py` (`runner.py` keeps model-building and the smoke harness). One entry point preserved.
3. check_data.py's first disjointness pass flagged train_1M ∩ train_10M — that overlap is by design (same pool, different budget); the check now tests pool-vs-held-out only.
4. The Windows "exit code 1" on prepare_data was PowerShell wrapping the unauthenticated-HF stderr warning; the script completed (manifest written). Unauthenticated download worked fine.
5. The resume test simulates the kill by finalizing a short run and deleting its result.json; the property being verified (RNG/momentum/data continuity) is identical to a hard kill, which is flaky to fake on Windows.
6. Benchmarks run on synthetic data (no FineWeb needed for T1).
