## Tier R addendum 4 (2026-10-17, zombie-OOM root cause)

Correction: the second batch of M-backprop OOM rows (K=0 columns) came from the session
still running the PRE-micro-batch zip - so they were the original OOM repeating, not a
failure of the fix. Root-causing them anyway exposed a latent bug in the shipped retry
logic: a failed attempt's partial autograd graph is a reference cycle (grad_fn <-> ctx <->
saved tensors) held further by the exception's traceback inside the except block, so
empty_cache() ran while the zombie was still alive and every retry would have OOM'd
against it (the pasted errors' ~21 GB "allocated" at a 1-sequence attempt is the
signature). Fixed: gc.collect() after the exception is released, before the retry; the
queue also gc-collects after failed runs; the OOM test asserts collection happens.
colab_tier_r.py now passes --retry-failed by default (the 3 M-backprop rows are at 2
failed attempts; flip RETRY_FAILED=False once they complete). First M Dust ladder point
landed meanwhile: M/1M K=1024 s0 = 5.9421 vs Appendix C 5.934 (within 0.008; params
37,749,776 = the paper's 37.7M exactly; wall 5,639 s ~ 22% faster than the benchmark
estimate).
